# randname 帮助

randname 是用于课堂点名的桌面程序。“模式”菜单提供单抽、多抽、减量抽、滚动单抽、滚动多抽和滚动减量抽。

## 抽取方式

- **单抽：** 不是独立页面，而是自动切到多抽并把人数设为 `1` 的快捷方式。
- **多抽：** 使用数量旁的加减按钮或纵向滑动条设置人数，再按“抽取”。同一次抽取不会重复选中同一个人；下一次抽取会重新使用完整名单。
- **减量抽：** 本次抽中的人会从当前运行中的剩余名单移除。“重置”会恢复当前名单。切换名单或刷新后名单内容有变化时，剩余名单会重置。
- **滚动单抽：** 不是独立页面，而是自动切到滚动多抽并把人数设为 `1` 的快捷方式。
- **滚动多抽：** 先用纵向滑动条或加减按钮设置人数，按“抽取”后显示相应数量的固定格子并同时轮播。第一次抽取时会确定格子位置（例如 6 人排成 3×2、居中显示），之后每按一次“停止”固定一个名字，已固定的名字不会因其他名字滚动而移动。若某个名字过长，程序会重新调整格子或字号并锁定；下一轮抽取或更改人数时重新布局。本轮已停下的名字不会再次出现。滚动速度由 `scroll.rate` 控制。
- **滚动减量抽：** 滚动与固定格子方式与滚动多抽相同，但本轮抽中的名字会从剩余名单移除；右侧“重置”按钮恢复完整名单。滚动速度同样由 `scroll.rate` 控制。

四个带数量控制的页面都提供纵向滑动条：范围从 `1` 到当前名单人数，可直接拖动或用触控调节，并与加减按钮、数量显示框实时同步。切换名单或刷新配置后，超出新名单人数的数量会自动夹紧。

输出框不会改变窗口大小：非滚动模式的名字能单行显示时单行显示，放不下且高度足够时自动换行，仍然放不下时缩小字号；滚动模式把每个名字放在固定格子中，只有名字放不进格子时才缩小字号。若最小字号仍然放不下，输出框会临时占用窗口上下的空白区域，人数少时自动恢复原尺寸。姓名间距经过紧凑化，大屏下滚动格子按内容宽度收拢并居中，不会把名字拉得过于分散。

## 名单

从“名单”菜单切换名单。名单配置位于 `config/name.toml`；每组名单有固定键名、多语言显示名称和人员列表：

```toml
[rosters.class_1.name]
en_US = "Class 1"
zh_CN = "一班"
zh_TW = "一班"

[rosters.class_1.names]
"student-001" = "王小明"
"student-002" = "陈小华"
```

每位人员须使用唯一键。名单名称按当前界面语言、系统语言、英语、名单键名的顺序回退。主名单不可用时，程序会尝试 `.name.default.toml`，最后使用内建的一人名单。

## 语言与主题

在“语言”菜单选择界面语言。语言包位于 `config/language.toml`，其中 `preferred` 指定首次启动的首选语言；旧配置中的 `app.language` 仅作为后备，`language.toml` 的 `preferred` 优先。英语为内建语言，即使语言文件缺失也可使用。切换语言立即生效，不会清除当前抽取结果。

主题集中保存在 `config/theme.toml`，其中 `default` 设置默认回退主题。主题名称与名单名称使用相同的多语言回退顺序。“主题”菜单按深色、浅色分两列展示；浅色主题使用带主题色的柔和底色，避免纯白刺眼。

可在单个主题内新增 `[themes.<键名>.background]` 表来显示背景图；`image` 相对 `ui/` 解析。支持 `cover`、`contain`、`center`、`tile` 裁切，以及 `uniform`、`horizontal`、`vertical`、`diagonal`、`center-out`、`out-center` 六种模糊方向；未设置图片的主题不显示背景。`randname-bg-light` 是可直接切换的示例主题，默认 `randname-dark` 的外观保持不变。背景图只显示在中央内容区，菜单栏与状态栏保持主题底色并加上阴影。结果框颜色由每个主题的 `[themes.<键名>.output]` 表控制：`background` 是底色、`foreground` 是文字颜色、`border` 是边框颜色；旧版的 `colors.display_*` 仍可作为后备。菜单栏和状态栏始终使用主题底色。Windows 11 会通过 DWM 让标题栏跟随主题色；Windows 10 只切换深浅色。

程序不会记住上次使用的主题、名单、日志等级、模式、语言、数量或窗口尺寸；每次启动都从配置档与独立配置档读取，保证界面状态一致。记忆文件只用于保存和导入/导出各模式的最近结果。

## 窗口与状态栏

主窗口默认允许拖动边缘拉伸，但下次启动仍使用 `[window]` 中配置的初始尺寸，不会记住上次拉伸后的尺寸。窗口尺寸不会因为名字过长或导入记忆而改变。将 `size_mode` 设为 `"maximum"` 时，程序启动即以最大化显示。`size_mode = "fixed"` 且宽或高大于可用屏幕时，程序会临时最大化；不会改写配置文件，还原时使用不超出屏幕的尺寸。把 `[window]` 的 `fullscreen` 设为 `true` 可让程序启动后直接进入全屏，该项优先于 `size_mode`。

状态栏左侧显示“抽取完成”等临时消息，右侧显示当前模式、名单、数量、主题、语言、日志等级和版本号。可在 `[statusbar]` 中逐项隐藏。

## 设置

在 `config/config.toml` 设置启动模式、名单、启动画面、窗口尺寸、输出字号、滚动速度、查看器、状态栏、日志等级和更新超时；主题与语言分别以 `theme.toml`、`language.toml` 独立配置档为准。配置文件内每个选项都有中文注释。图标、启动画面、帮助、许可证、日志与记忆文件位置固定于程序代码，不再通过配置修改。

```toml
[window]
size_mode = "screen_ratio"   # 或 "fixed"、"maximum"
fullscreen = false           # true 时启动即全屏
screen_ratio = 0.75          # 初始尺寸占可用屏幕的比例
aspect_ratio = 1.5
width = 1000
height = 600
resizable = true

[scroll]
rate = 30

[splash]
enabled = true
mode = 1
duration_ms = 1000
screen_ratio = 0.25
```

比例模式下，启动画面不超过可用屏幕的 `screen_ratio`；主窗口按 `screen_ratio` 与 `aspect_ratio` 计算初始尺寸。启动画面 `mode = 0` 时主窗口准备好即关闭；`mode = 1` 时至少显示 `duration_ms` 毫秒，时间到后才显示主窗口，避免主窗口遮住启动画面。启动画面右下角会动态显示当前版本号。

修改配置、名单、语言包或主题后，使用“文件 > 刷新程序状态”。只要原选项仍有效，程序会保留当前模式、主题、语言、名单、结果与状态；若所选资源已被移除，则回退到可用选项。

## 日志与记忆

在“关于 > 日志等级”选择调试、信息、警告、错误或严重错误；该等级只控制写入 `doc/log.log` 的详细程度。“关于 > 程序日志”始终显示本次运行的全部等级，并在行首按等级高亮，方便排查问题。

“文件 > 导入记忆...”和“文件 > 导出记忆...”使用 JSON 保存或恢复最近结果，不会覆盖程序配置、名单或界面状态。运行记忆文件为 `doc/memory.json`，只保存各模式的最近结果。

“文件 > 初始化”会清空 `doc/memory.json`，把所有模式的数量恢复为 1 并清除已显示的结果；不会删除 `doc/log.log`，初始化动作本身会写入日志。

帮助、许可证和程序日志都在程序自身的只读查看器中显示。查看器窗口会限制在桌面可用区域内，为任务栏留出空间；支持触摸拖动滚动，并可通过 `[viewer]` 调整字号和刷新间隔。

“关于 > 检查更新”会异步查询 GitHub Releases。窗口顶部用大字号显示检测中、已是最新版本、检测到新版本或查询失败；下方显示 `doc/history.md` 正文。只有检测到新版本时“更新”才可用，点击后打开 Releases 页面并关闭窗口；“手动查询”始终打开 Releases 页面且不关闭窗口；“确定”只关闭窗口。网络不可用或 GitHub 限流时，请使用“手动查询”。

## 启动与故障排除

程序先显示启动画面，再检查数据并初始化主窗口。配置、名单、语言或主题缺失时会使用备份或内建数据，并仅在状态栏和日志中提示；缺少程序本体组件时才弹出详细错误并停止启动。

编辑文件后若选项不可用，请执行“文件 > 刷新程序状态”。若当前语言的帮助文档不存在，“帮助”会打开英文文档。“关于 > 反馈”包含 GitHub Issues 与电子邮件两个条目；无法唤起邮件程序时会弹窗显示邮箱地址。
